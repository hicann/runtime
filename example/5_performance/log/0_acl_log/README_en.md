## 0_acl_log

This sample demonstrates the public ACL logging APIs in `acl_log.h`: recording debug and run logs, recording through `va_list`, and registering and unregistering a device log callback.

## Build and run

Run the parent directory's `run.sh` in a CANN environment:

```bash
source ${install_root}/cann/set_env.sh
cd ${git_clone_path}/example/5_performance/log
bash run.sh
```

The script checks both the build and the sample output and returns a non-zero status on failure.

## Artifacts

### Build artifacts

- Executable: `example/5_performance/log/build/0_acl_log/acl_log_sample`
- Run output: `example/5_performance/log/0_acl_log/output_msg.txt` (full stdout, generated by `run.sh`)

### Expected output (stdout)

With the default configuration and the logging APIs available, the output is as follows (the value returned by `acllogCheckDebugLevel` depends on the module's current log level configuration; it is 0 when the default debug log level `DLOG_ERROR` applies):

```text
[INFO] acllogCheckDebugLevel returned 0.
[SUCCESS] ACL log sample completed successfully.
```

If device-side plog reports exist in the runtime environment, the callback additionally prints `[CALLBACK type=N] ...` lines. If the optional logging APIs are unavailable on the current product (weak symbols are null), a `[WARN]` message is printed and the sample still exits normally.

If `export ASCEND_LOG_PRINT_TO_STDOUT=1` is set before running (the legacy variable `ASCEND_SLOG_PRINT_TO_STDOUT` is deprecated and not recommended), the recorded log content is additionally printed to stdout, so the output also includes the log entries themselves.

### Log file locations

By default (when `ASCEND_LOG_PRINT_TO_STDOUT` is not enabled), logs recorded by `acllogRecord` and `acllogVaList` are not printed to stdout. They are written to the host log directory: the path specified by the `ASCEND_PROCESS_LOG_PATH` environment variable takes precedence, then the `log` directory under `ASCEND_WORK_PATH`, and the default is `~/ascend/log` when neither is set. Debug logs go to the `debug` subdirectory and run logs (moduleId carrying `RUN_LOG_MASK`) go to the `run` subdirectory; user module IDs (`0xff00`-`0xffff`) are recorded as decimal IDs in the logs.
