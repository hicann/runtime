# Dump File Analysis

This document describes Dump file directories, conversion methods, and common field meanings. For the API usage sequence and parameter constraints, see the [Dump configuration API reference](../../../docs/zh/api_ref/18_dump_configuration.md).

## File Paths

Dump file directories depend on the Dump type, configuration, and environment variables:

- For model Dump, single-operator data Dump, and overflow operator Dump, the file directory is specified by `dump_path` in the configuration file. Environment variables do not override this path.
- Operator information statistics files are specified by the `path` parameter of `aclopStartDumpArgs(uint32_t dumpType, const char *path)`. This API outputs operator information files and does not output tensor data files.
- Call `acldumpGetPath(acldumpType dumpType)` to query the current output path of a Dump type.
- The root path of Exception operator Dump is `<dumpPath>/extra-info/data-dump/<deviceId>/`. Its path priority is `ASCEND_DUMP_PATH` > `ASCEND_WORK_PATH` > `dump_path` in the configuration file > current directory `./`. You can also call `acldumpGetExceptionInfoPath(char *path, size_t maxLen)` to query it.

Common Dump types:

| Type | Description | Path locating method |
| --- | --- | --- |
| Model Dump | Exports input and output data of operators in a model. | `dump_path` in the configuration file. |
| Single-operator data Dump | Exports input and output tensor data of a single operator. | `dump_path` in the configuration file. |
| Operator information statistics | Exports operator information files, including operator type, attributes, input/output format, data type, and shape. | The `path` parameter of `aclopStartDumpArgs`. |
| Overflow operator Dump | Exports input and output data of overflow operators. | `dump_path` in the configuration file. |
| Exception operator Dump | Exports input, output, workspace, Tiling, and other information of exception operators. | `ASCEND_DUMP_PATH`, `ASCEND_WORK_PATH`, `dump_path` in the configuration file, or `<dumpPath>/extra-info/data-dump/<deviceId>/` under current directory `./`. |

## Conversion and Analysis

Convert tensor Dump files to a format that is easy to inspect. The following example uses NumPy:

```bash
msaccucmp.py convert -d <dump_file> -out <output_dir>
```

Files generated by `aclopStartDumpArgs` are operator information files and are not applicable to the tensor Dump conversion command above.

After conversion, use Python to inspect NumPy data:

```python
import numpy as np

data = np.load("<converted_file>.npy")
print(data.shape)
print(data.dtype)
print(data)
```

For large data, check the shape, dtype, maximum value, minimum value, and whether NaN or Inf exists first:

```python
import numpy as np

data = np.load("<converted_file>.npy")
print("shape:", data.shape)
print("dtype:", data.dtype)
print("min:", np.nanmin(data))
print("max:", np.nanmax(data))
print("has_nan:", np.isnan(data).any())
print("has_inf:", np.isinf(data).any())
```

## Callback Fields

After `acldumpRegCallback` is used to register a callback, the callback function can obtain chunked Dump data through `acldumpChunk`. Common fields are as follows:

| Field | Meaning | Analysis suggestion |
| --- | --- | --- |
| `fileName` | Absolute file name where Dump data was originally planned to be written. | Used to merge chunks of the same tensor or the same Dump by file name. |
| `bufLen` | Byte length of `dataBuf`. | Used to determine the data size carried by the current callback. |
| `isLastChunk` | Whether this is the last chunk. `0` indicates no, and `1` indicates yes. | Only after the last chunk is received can the file data be considered complete. |
| `offset` | Offset used when the current chunk is written to the file. `-1` indicates append. | Used to restore chunked data by offset. |
| `flag` | Reserved flag. | No specific flag is currently defined. Usually it only needs to be recorded. |
| `dataBuf` | Address of Dump data content. | Read byte data according to `bufLen`, and then parse it together with the file name or metadata. |

## Tensor Fields

In Exception operator Dump or custom tensor save scenarios, key fields of `acldumpTensorInfo` are as follows.

| Field | Meaning | Analysis suggestion |
| --- | --- | --- |
| `type` | Tensor type, such as input or output. | Used to determine the role of the data in the operator. |
| `tensorSize` | Tensor data size, in bytes. | Compare it with the result calculated from shape and dataType to determine whether the data is complete. |
| `format` | Tensor format. | Compare it with the operator's expected format to troubleshoot format mismatch. |
| `dataType` | Tensor data type. | Required for interpreting raw bytes during conversion or inspection. |
| `tensorAddr` | Tensor data address. | Used to identify the data address to be saved. |
| `addrType` | Tensor address type. | Must be `ACL_DUMP_ADDR_RAW` when `acldumpSaveExceptionInfo` is called, indicating that `tensorAddr` is a raw data address on Device. |
| `placement` | Tensor data placement. | Must be `ACL_DUMP_PLACEMENT_DEVICE` when `acldumpSaveExceptionInfo` is called, indicating that Device-side data is read. |
| `shapeNum` | Number of valid dimensions in `shape`. | Must not exceed 25; otherwise, the API returns `ACL_ERROR_INVALID_PARAM`. If it is not set or is 0, the current shape in the saved file is empty. |
| `originShapeNum` | Number of valid dimensions in `originShape`. | Must not exceed 25. In dynamic shape or format conversion scenarios, it must be consistent with valid dimensions in `originShape`. |
| `shape` | Current tensor shape. | Only the first `shapeNum` dimensions are valid. Compare them with the model or operator input and output specifications. |
| `originShape` | Original tensor shape. | Only the first `originShapeNum` dimensions are valid. Use it to trace the original dimensions in dynamic shape or format conversion scenarios. |

## Analysis Suggestions

- First confirm whether files are generated according to the path priority, `dump_path`, or the path returned by the API, and then select the files to be converted and inspected.
- When comparing accuracy issues, first confirm whether shape, dataType, and format meet expectations, and then compare numerical differences.
- For Exception operator Dump, first check the exception operator name, input, output, workspace, and Tiling information, and then locate the issue together with Runtime logs or AI Core Error information.
- For chunked callback data, restore the complete file according to `fileName`, `offset`, and `isLastChunk` before analysis.
