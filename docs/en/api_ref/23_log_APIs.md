# 23. Log APIs

This chapter describes the log APIs, which are used to record logs generated by modules and validate the debug log level.

- [Usage Notes](#usage-notes)
- [`int32_t AlogRecord(uint32_t moduleId, uint32_t logType, int32_t level, const char *fmt, ...)`](#AlogRecord): Records logs generated by each module.

- [`void acllogRecord(int32_t moduleId, int32_t level, const char *fmt, ...)`](#acllogRecord): Records logs generated by user modules.
- [`void acllogVaList(int32_t moduleId, int32_t level, const char *fmt, va_list list)`](#acllogVaList): Records logs generated by user modules through va_list.
- [`int32_t acllogCheckDebugLevel(int32_t moduleId, int32_t logLevel)`](#acllogCheckDebugLevel): Validates the debug log level of user modules.

## Usage Notes

These APIs are used only in scenarios where CANN components are customized and developed. This document describes the functions and parameters of these APIs, so that you can understand their roles in the CANN open-source code and thereby better use or modify the CANN open-source code.

The paths of the log API header files and library files involved are as follows:

- Path of the included header file: ${INSTALL_DIR}/include/base/alog_pub.h. This header file already includes log_types.h.
- Path of the log callback API header file: ${INSTALL_DIR}/include/base/acl_log.h
- Path of the dependent library file: ${INSTALL_DIR}/lib64/libascendalog.so

Custom modules can use the `acllogRecord`, `acllogVaList`, and `acllogCheckDebugLevel` interfaces in `acl_log.h` to record logs. The `moduleId` for custom modules ranges from `0xff00` to `0xffff` (65280 to 65535). To record run logs, perform a bitwise OR operation on the custom `moduleId` and `RUN_LOG_MASK` before passing them in. The logs are then written to the run directory. Run logs do not record debug-level logs. When `moduleId` carries `RUN_LOG_MASK`, the `level` must not be `DLOG_DEBUG`; otherwise, the log will not be written to disk. If no log type mask is carried, the log is treated as a debug log by default. The `moduleId` within this range is recorded as a decimal ID in the logs and is not converted to a `moduleName` string. The `moduleId` of internal CANN modules ranges from `0x0000` to `0x00ff` (0 to 255).

Replace ${INSTALL_DIR} with the file storage path after the CANN software is installed. Taking installation by the root user as an example, the default file storage path after installation is /usr/local/Ascend/cann.

### Description

>**Note:**
>This API will be deprecated in later versions. It is not recommended for use to avoid compatibility issues.

Records logs generated by each module.

### Parameters

| Parameter | Input/Output | Description |
| --- | --- | --- |
| moduleId | Input | Module ID. For enumeration values, see [Data Type Definition](#data-type-definition). |
| logType | Input | Type of this log entry. For enumeration values, see [Data Type Definition](#data-type-definition). Other values are treated as debug logs. |
| level | Input | Level of this log entry. For the macro definition, see [Data Type Definition](#data-type-definition).<br> Note: Run logs do not record debug-level logs. DLOG_TYPE_RUN and DLOG_DEBUG cannot be used together. |
| fmt | Input | Content to be printed.<br><br>  - The API does not validate the content.<br>  - The maximum length of a single log entry is 1024 bytes. Content exceeding this length is truncated. |

### Return Values

Returns 0 on success and other values on failure.

### Example

```c
AlogRecord(SLOG, DLOG_TYPE_RUN, DLOG_INFO, "test run log");
```

### Description

Registers a callback function for device plog logs. After registration is successful, the plog logs reported on the device trigger the callback before the original write-to-disk process.

Multiple callback functions can be registered, up to 16. The return value of a callback function is ignored and does not affect the original plog write-to-disk process or the execution of other registered callback functions.

>**Note:**
>This API takes effect only on the device plog report reporting path and does not cover ordinary AlogRecord/DlogRecord logs on the host.

### Parameters

| Parameter | Input/Output | Description |
| --- | --- | --- |
| callbackFunc | Input | Callback function. For details about the type, see [Data Type Definition](#data-type-definition). NULL is not allowed. |
| userData | Input | Custom data. This data is passed back through the userData parameter of the callback function when the callback is triggered. NULL is allowed. |
| outputLogType | Input | Log output type received by the callback. For details about the enumeration values, see [Data Type Definition](#data-type-definition). |
| callbackHandle | Output | Callback handle returned after successful registration, used for unregistering. NULL is not allowed. |

### Return Values

Returns the callback registration result.

0: Registration successful

-1: Registration failed. Failure scenarios include callbackFunc being NULL, callbackHandle being NULL, an invalid outputLogType, or the number of registered callback functions reaching 16.

### Example

```c
static int32_t LogCallback(void *userData, uint32_t outputLogType, const char *logContent, size_t length)
{
    (void)userData;
    (void)outputLogType;
    printf("%.*s", (int)length, logContent);
    return 0;
}

acllogCallbackHandle handle = 0;
int32_t ret = acllogRegisterCallback(LogCallback, NULL, OUTPUT_TYPE_BOTH, &handle);
```

## Data Type Definition

Log level macro definition:

```c
#define DLOG_DEBUG 0x0      // Debug level ID
#define DLOG_INFO  0x1      // Info level ID
#define DLOG_WARN  0x2      // Warning level ID
#define DLOG_ERROR 0x3      // Error level ID
```

Log type enumeration:

```c
enum {
    DLOG_TYPE_DEBUG = 0,    // Debug log
    DLOG_TYPE_RUN = 1,      // Run log
    DLOG_TYPE_MAX           // Invalid value
};
```

Log callback output type enumeration:

```c
typedef enum {
    OUTPUT_TYPE_DEBUG = 0,  // Debug log
    OUTPUT_TYPE_RUN = 1,    // Run log
    OUTPUT_TYPE_BOTH = 2,   // Debug Log and Run log
    OUTPUT_TYPE_MAX         // Invalid value
} acllogOutputLogType;
```

Log callback handle type:

```c
typedef uintptr_t acllogCallbackHandle;
```

Log callback function type:

```c
typedef int32_t (*acllogRecordCallback)(
    void *userData, uint32_t outputLogType, const char *logContent, size_t length);
```

Parameters:

| Parameter | Description |
| --- | --- |
| userData | Custom data passed in when the user registers the callback function. |
| outputLogType | Log output type that currently triggers the callback. The value can be OUTPUT_TYPE_DEBUG, OUTPUT_TYPE_RUN, or OUTPUT_TYPE_BOTH. |
| logContent | Log content. |
| length | Length of the log content, in bytes. |
