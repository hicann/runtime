# 改动检查清单

## 先判断范围

- 确认用户提供的 CANN API、目标产品和期望结果。
- 确认这些 API 能组成一个有明确目标、操作和结果的实际场景。
- 确认场景只使用一个 Device，并排除 P2P、设备拓扑、跨 Device 内存等多 Device API。
- 相关 API 组成一个完整样例；不相关的 API 按独立场景拆分。
- 只创建新的编号样例，不修改已有可运行样例或无关文档。

## 核对 API 准入

- 在正式 API 文档中逐个确认接口公开、未废弃，并记录其对 A2、A3、A5 和当前 CANN 版本的支持情况；不能用头文件存在、编译成功或其他产品运行成功替代产品支持证据。
- 以全部关键 API 产品支持范围的交集作为样例支持范围。任一关键 API 不支持目标产品时停止为该产品生成或运行样例；支持证据缺失时不得猜测为支持。
- 在目标仓库或安装包公开头文件中确认声明；动态接口按需确认发布库符号。
- 检查参数、对象生命周期和调用顺序符合公开契约。
- 确认每个 API 都推动场景流程、影响决策、参与结果校验或完成必要清理。
- 排除只能用于接口罗列、无法服务于实际场景的 API。
- 记录未纳入 API 及其公开性、版本、产品支持或合法输入方面的原因。

## 检查应更新的文件

可运行样例通常需要检查：

- 源文件
- `README.md`
- `README_en.md`
- `CMakeLists.txt`
- `run.sh`

上述两份 README 都是必需文件；缺少任一文件时样例不得通过交付检查。

按需再检查主题 `README.md`、顶层 `example/README.md` 和共享辅助文件引用。

## 保持代码和文档一致

- 关键流程步骤使用简短英文注释，不注释显而易见的单行语句。
- 新样例中的相对 include、共享源码引用和输出路径正确。
- `README.md` 和 `README_en.md` 中的路径、API、产品支持情况、编译运行说明和示例输出彼此一致，并与实现一致。
- 具体样例 README 使用 `## 描述`，不保留 `## 概述`、`## 功能说明` 或空的 `## 已知 issue`。
- 功能和特性名称使用公开正式叫法，不使用内部简称。

## 静态检查

- 搜索新样例中的废弃 API，以及 README 中多写或漏写的 API。
- 检查 `CMakeLists.txt` 的源文件、头文件路径和链接库；普通 Runtime 样例优先链接 `libacl_rt.so`。
- 检查 `run.sh` 使用 LF、具有有效 shell 语法，并能把构建或程序失败传播为非零退出码。
- 检查 `README.md` 和 `README_en.md` 均存在，并检查两者的链接、产品支持表和示例输出格式；产品支持表必须与关键 API 支持范围的交集一致。

## 本地交付检查

- 完成全部编辑后维护本任务的显式文件清单。清单必须包含尚未被 Git 跟踪的新文件，以及本任务修改的源码、头文件、Kernel、双语 README、`CMakeLists.txt`、`run.sh` 和父级 README；不得把用户的无关改动加入检查或格式化范围。
- 读取目标仓库当前版本的 `.pre-commit-config.yaml`、`.clang-format`、`OAT.xml` 和仓库说明，并对完整任务文件清单执行仓库定义的本地 hook。仓库使用 Pre-commit 时执行：

  ```bash
  pre-commit run --show-diff-on-failure --files "${task_files[@]}"
  ```

- 同时对工作区执行 `git diff --check`，并对本任务修改的每个 Shell 脚本执行 `bash -n`。
- 任一检查失败或改写文件时，检查差异、修复问题，并对相同文件清单复跑，直到所有可执行检查以 0 退出且不再产生改动。
- Pre-commit 或仓库工具不可用时，直接运行仓库声明的格式化工具，并完成仍可执行的 `git diff --check` 和 Shell 语法检查。交付时记录未执行项、原因和复现命令，不得把替代检查表述为完整通过。

## 构建与运行

- 运行前通过设备查询工具确认实际产品型号，并与 README 产品支持表核对。只在标记支持的产品上运行；当前设备不受支持时跳过执行并记录原因，不把预期的不支持错误当成样例缺陷，也不宣称该产品已验证。
- 按 README 加载目标 CANN 和仓库环境，执行每个新增样例的 `bash run.sh` 或等价仓库命令。
- 确认构建成功、程序退出码符合预期，且没有未处理的错误日志。
- 校验数据、状态、回调或资源关系等业务结果，不能只检查 API 返回成功。
- 确认失败路径不会输出成功标记，主流程结束后资源得到清理。
- 只有真实运行成功后才更新 README 示例输出；环境相关值用 `...` 表示。
- 新样例使用公共依赖时，确认没有修改这些共享文件。

缺少工具链、环境变量或目标设备时，执行仍可完成的静态检查，并在交付结果中列出未执行项、原因和复现命令，不宣称完整验收。
